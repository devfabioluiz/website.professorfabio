Operadores Condicionais e ENUM

Tópicos do nosso plano de curso abordados nessa aula: Operadores condicionais (if, if else, if else if, switch), Tipos de dados (ENUM), const enum, union types, nullish coalescing, optional chaining, discriminated unions.

Operadores Condicionais

Operadores condicionais permitem que o programa tome decisões com base em condições. São a base da lógica de qualquer aplicação — sem eles, não seria possível reagir a diferentes situações.

if

Verifica uma condição. Se for true, executa o bloco de código. 

const usuarioEstaLogado: boolean = true;

if (usuarioEstaLogado) {
  console.log("Bem-vindo ao painel!");
}

Explicando o código

A variável usuarioEstaLogado é do tipo boolean. Como seu valor é true, o bloco do if é executado e a mensagem é exibida no console. Se fosse false, nada aconteceria.

if...else

Executa um bloco se a condição for verdadeira e outro se for falsa. 

const saldo: number = 200;
const valorCompra: number = 350;

if (saldo >= valorCompra) {
  console.log("Compra aprovada!");
} else {
  console.log("Saldo insuficiente.");
}

Explicando o código

O TypeScript compara se saldo (200) é maior ou igual a valorCompra (350). Como 200 < 350, a condição é falsa e o bloco do else é executado — exibindo "Saldo insuficiente."

if...else if...else

Permite múltiplas condições encadeadas em sequência.

const nota: number = 72;

if (nota >= 90) {
  console.log("Excelente!");
} else if (nota >= 70) {
  console.log("Bom trabalho!");
} else if (nota >= 50) {
  console.log("Aprovado.");
} else {
  console.log("Reprovado.");
}

Explicando o código

O TypeScript avalia as condições de cima para baixo. A nota 72 não atinge 90, mas atinge 70 — então else if (nota >= 70) é executado. Assim que uma condição é satisfeita, as demais são ignoradas.

Dica: Organize sempre do valor mais alto para o mais baixo. Se colocasse nota >= 50 primeiro, uma nota de 72 cairia nele e os outros blocos nunca seriam avaliados.

switch

Ideal quando você precisa comparar uma variável contra vários valores fixos. Mais limpo que múltiplos else if quando os valores são conhecidos. 

const metodoPagamento: string = "pix";

switch (metodoPagamento) {
  case "pix":
    console.log("Pagamento instantâneo via PIX.");
    break;
  case "credito":
    console.log("Parcelamento em até 12x.");
    break;
  case "debito":
    console.log("Pagamento à vista no débito.");
    break;
  default:
    console.log("Método de pagamento inválido.");
}

Explicando o código

O switch compara metodoPagamento com cada case. Quando encontra "pix", executa aquele bloco e o break impede que continue para os próximos cases.

O default funciona como um "else" — executa quando nenhum case é correspondido. É boa prática sempre incluí-lo para tratar valores inesperados.

Importante: Sempre use break ao final de cada case. Sem ele, o JavaScript "cai" no próximo case mesmo sem a condição ser verdadeira (chamado fall-through).

Comparação: if vs switch

Cenário Melhor opção Por quê?
Comparar intervalos (ex: nota >= 70) if...else if Switch não trabalha com ranges
Comparar uma variável contra vários valores fixos switch Mais legível e performático
Condições complexas (AND, OR) if Switch só compara igualdade

O que é enum em TypeScript?

enum (abreviação de enumeration) é uma construção do TypeScript que permite declarar um conjunto de constantes nomeadas. É como criar um "dicionário fixo" de valores que o seu código pode usar.

Imagine que você está construindo um sistema de pedidos. Em vez de espalhar strings como "pendente", "processando", "concluido" por todo o código (e correr o risco de digitar errado), você centraliza tudo em um enum.

Por que usar enum?

  • Segurança de tipo: O TypeScript impede que você use valores que não existem no enum. Se digitar errado, o compilador avisa.
  • Legibilidade: Em vez de status === "PENDENTE", você usa status === StatusPedido.Pendente — muito mais claro.
  • Manutenibilidade: Se precisar renomear um valor, você muda em um único lugar e o TypeScript atualiza em todo o projeto.
  • Autocomplete: Sua IDE mostra todas as opções disponíveis ao digitar o nome do enum.

Enum numérico

Por padrão, o TypeScript atribui valores numéricos incrementais a partir de 0. 

enum DiaSemana {
  Domingo,    // 0
  Segunda,    // 1
  Terca,      // 2
  Quarta,     // 3
  Quinta,     // 4
  Sexta,      // 5
  Sabado      // 6
}

const hoje: DiaSemana = DiaSemana.Quarta;

console.log(hoje);            // 3
console.log(DiaSemana[hoje]); // "Quarta" (busca reversa)

Explicando o código

O enum DiaSemana começa em 0 automaticamente. Quando atribuímos DiaSemana.Quarta à variável hoje, o valor armazenado é 3. A expressão DiaSemana[hoje] faz a busca reversa: dado o número 3, retorna a string "Quarta".

Essa busca reversa é uma particularidade dos enums numéricos em TypeScript. Ela pode ser útil para logs, mas deve ser usada com cuidado em tempo de execução.

Enum de string

Mais recomendado para a maioria dos casos. Os valores ficam mais legíveis nos logs e na depuração. 

enum StatusPedido {
  Pendente = "PENDENTE",
  Processando = "PROCESSANDO",
  Enviado = "ENVIADO",
  Entregue = "ENTREGUE",
  Cancelado = "CANCELADO"
}

function exibirStatus(status: StatusPedido): void {
  console.log(`Status atual: ${status}`);
}

exibirStatus(StatusPedido.Enviado); // Status atual: ENVIADO

Explicando o código

Cada membro do enum recebe uma string como valor. Quando chamamos StatusPedido.Enviado, o valor real é "ENVIADO". Isso torna os logs muito mais legíveis — em vez de vermos o número 2, vemos a palavra completa.

Outra vantagem: se alguém tentar passar uma string que não existe no enum, o TypeScript gera um erro de compilação. Exemplo: exibirStatus("enviado") gera erro — o correto é StatusPedido.Enviado.

Enum personalizado (começando de 1)

Você pode definir os valores manualmente. Útil quando os números têm significado (como níveis de acesso). 

enum NivelAcesso {
  Leitor = 1,
  Editor = 2,
  Administrador = 3
}

function podeEditar(nivel: NivelAcesso): boolean {
  return nivel >= NivelAcesso.Editor;
}

console.log(podeEditar(NivelAcesso.Leitor));        // false
console.log(podeEditar(NivelAcesso.Administrador)); // true

Explicando o código

Ao atribuir Leitor = 1, os valores seguintes continuam incrementando normalmente (Editor = 2, Administrador = 3). A função podeEditar usa comparação numérica — alguém com nível 2 ou superior pode editar.

Cuidado: Essa comparação numérica funciona porque os valores são inteiros crescentes. Se os valores fossem strings, essa abordagem não funcionaria.

const enum — performance otimizada

Quando você marca um enum com const, o TypeScript remove o objeto enum do código compilado e substitui os valores diretamente. Isso gera um JavaScript menor e mais rápido. 

// Enum normal — gera um objeto no JS compilado
enum Cor {
  Vermelho,
  Verde,
  Azul
}

// const enum — os valores são substituídos inline (mais leve)
const enum CorOtimizada {
  Vermelho,
  Verde,
  Azul
}

const cor: CorOtimizada = CorOtimizada.Verde;
console.log(cor); // 1

Explicando o código

Um enum normal gera algo como var Cor; (function(Cor) { Cor[Cor["Vermelho"] = 0] = "Vermelho"; ... }) no JavaScript final. O const enum não gera nada — ele é "embutido" diretamente onde é usado.

Quando usar: Prefira const enum quando você não precisa da busca reversa (ex: Cor[0]) e quer código mais leve. Para a maioria dos casos, enum normal já é suficiente.

Restrição: const enum não pode ser usado com computed values e tem limitações em módulos. Na dúvida, use enum normal.

Enum com switch — o padrão completo

A combinação de enum com switch é um dos padrões mais usados no TypeScript moderno. Veja um exemplo prático de sistema de pedidos: 

enum StatusPedido {
  Pendente = "PENDENTE",
  Processando = "PROCESSANDO",
  Enviado = "ENVIADO",
  Entregue = "ENTREGUE",
  Cancelado = "CANCELADO"
}

function processarPedido(status: StatusPedido): void {
  switch (status) {
    case StatusPedido.Pendente:
      console.log("Aguardando confirmação de pagamento...");
      break;
    case StatusPedido.Processando:
      console.log("Preparando seu pedido...");
      break;
    case StatusPedido.Enviado:
      console.log("Pedido a caminho! Código de rastreio: BR123456");
      break;
    case StatusPedido.Entregue:
      console.log("Pedido entregue. Avalie sua experiência!");
      break;
    case StatusPedido.Cancelado:
      console.log("Pedido cancelado. Estorno será processado em 3 dias úteis.");
      break;
    default:
      console.log("Status desconhecido.");
  }
}

processarPedido(StatusPedido.Enviado); // Pedido a caminho! Código de rastreio: BR123456

Explicando o código

Note que cada case usa StatusPedido.NomeDoStatus em vez de strings soltas. Se alguém digitar StatusPedido.Enviad (sem o "o"), o TypeScript gera um erro imediato — algo que não aconteceria com strings normais.

Esse padrão é extremamente comum em sistemas reais: gerenciar estados de pedidos, assinaturas, chamados de suporte, fluxos de aprovação, etc.

Enum vs Union Types — qual usar?

O TypeScript oferece uma alternativa moderna aos enums: as union types (união de tipos). Em muitos casos, elas são mais simples e leves. 

// Com enum
enum Status {
  Ativo = "ATIVO",
  Inativo = "INATIVO"
}

// Com union type (mais leve)
type StatusAlternativo = "ATIVO" | "INATIVO";

// Ambos funcionam assim:
const usuarioStatus: Status = Status.Ativo;
const usuarioStatusAlt: StatusAlternativo = "ATIVO";

// E o TypeScript protege contra valores inválidos:
// const erro: StatusAlternativo = "inativo"; // ERRO de compilação!

Explicando o código

A union type define que StatusAlternativo só pode ser "ATIVO" ou "INATIVO". Qualquer outro valor gera erro. É mais enxuto que enum e não gera nenhum código JavaScript extra.

Quando usar cada um

Abordagem Use quando... Exemplo
enum Precisa de busca reversa, valores numéricos, ou múltiplos membros Status de pedido, roles de usuário, dias da semana
type (union) Valores são strings simples, quer código mais leve Estados de UI, opções de filtro, métodos HTTP

Exemplo prático: métodos HTTP

type MetodoHTTP = "GET" | "POST" | "PUT" | "DELETE";

function fazerRequisicao(url: string, metodo: MetodoHTTP): void {
  console.log(`${metodo} ${url}`);
}

fazerRequisicao("/api/usuarios", "GET");     // OK
fazerRequisicao("/api/usuarios", "POST");    // OK
// fazerRequisicao("/api/usuarios", "PATCH"); // ERRO: "PATCH" não está no tipo

Explicando o código

Para métodos HTTP, uma union type é perfeita — são poucos valores fixos, todos strings, sem necessidade de busca reversa. O TypeScript garante que apenas valores válidos sejam usados.

Conceitos Modernos do TypeScript

O TypeScript evoluiu bastante nos últimos anos. Alguns recursos modernos se conectam diretamente com condicionais e enums, tornando o código mais seguro e conciso.

Nullish Coalescing (??)

O operador ?? retorna o valor à direita apenas quando o valor à esquerda for null ou undefined. Diferente do || que considera qualquer valor falso (0, "", false). 

const nomeDigitado: string | null = "";
const nomePadrao: string = "Visitante";

// Com || — valores falsos (0, "", false) também ativam o padrão
const nomeComOr = nomeDigitado || nomePadrao;
console.log(nomeComOr); // "Visitante" (mesmo que "" seja intencional!)

// Com ?? — só null/undefined ativam o padrão
const nomeComNullish = nomeDigitado ?? nomePadrao;
console.log(nomeComNullish); // "" (mantém o valor vazio, que é válido)

Explicando o código

O || trata "" como falsy, então substitui pelo padrão. Mas "" pode ser uma escolha válida do usuário. O ?? é mais preciso: só entra em ação quando o valor é null ou undefined.

Uso real: Configurações de aplicação, parâmetros de URL, dados de formulário com valores opcionais.

Optional Chaining (?.)

Acessa propriedades de forma segura. Se algum nível da cadeia for null ou undefined, retorna undefined em vez de lançar erro. 

type Usuario = {
  nome: string;
  endereco?: {
    cidade?: string;
    cep?: string;
  };
};

const usuarioComEndereco: Usuario = {
  nome: "Ana",
  endereco: {
    cidade: "São Paulo",
    cep: "01000-000"
  }
};

const usuarioSemEndereco: Usuario = {
  nome: "Carlos"
};

// Acesso seguro com optional chaining
console.log(usuarioComEndereco.endereco?.cidade); // "São Paulo"
console.log(usuarioSemEndereco.endereco?.cidade); // undefined (sem erro!)

// Encadeamento múltiplo
console.log(usuarioComEndereco.endereco?.cep?.toUpperCase()); // "01000-000"
console.log(usuarioSemEndereco.endereco?.cep?.toUpperCase()); // undefined

Explicando o código

Sem o ?., acessar usuarioSemEndereco.endereco.cidade geraria um erro: Cannot read properties of undefined. O optional chaining verifica cada nível antes de acessar o próximo.

O ? no tipo (endereco?: { ... }) indica que a propriedade é opcional — o objeto pode ou não tê-la. O ?. no acesso trata o caso de ela não existir.

as const — Assertions de constante

O as const força o TypeScript a tratar valores como literais fixos (não como tipos amplos). É uma alternativa leve a enums. 

// Sem as const — tipo é "string"
const cores = ["vermelho", "verde", "azul"];
// tipo: string[]

// Com as const — tipo é readonly com valores fixos
const coresFixas = ["vermelho", "verde", "azul"] as const;
// tipo: readonly ["vermelho", "verde", "azul"]

// Acesso por índice retorna o valor literal
type Cor = typeof coresFixas[number]; // "vermelho" | "verde" | "azul"

function pintar(cor: Cor): void {
  console.log(`Pintando de ${cor}...`);
}

pintar("vermelho"); // OK
// pintar("amarelo"); // ERRO: "amarelo" não está no tipo

Explicando o código

Sem as const, o TypeScript infere cores como string[] — qualquer string seria aceita. Com as const, cada elemento mantém seu valor literal e o array vira readonly (imutável).

A expressão typeof coresFixas[number] é um padrão avançado que extrai o tipo de todos os elementos do array, criando uma union type automaticamente. É como criar um enum sem declarar um.

Discriminated Unions — o padrão moderno

Uma discriminated union (união discriminada) combina interfaces com union types para criar estados bem definidos. É o padrão mais usado em aplicações TypeScript modernas. 

// Cada estado tem uma "propriedade discriminante" (kind)
type ResultadoBusca =
  | { kind: "carregando" }
  | { kind: "sucesso"; dados: Usuario[] }
  | { kind: "erro"; mensagem: string };

type Usuario = {
  id: number;
  nome: string;
};

function renderizarResultado(resultado: ResultadoBusca): void {
  switch (resultado.kind) {
    case "carregando":
      console.log("Carregando...");
      break;
    case "sucesso":
      console.log(`${resultado.dados.length} usuários encontrados`);
      break;
    case "erro":
      console.log(`Erro: ${resultado.mensagem}`);
      break;
  }
}

// Usando:
renderizarResultado({ kind: "carregando" });
renderizarResultado({
  kind: "sucesso",
  dados: [{ id: 1, nome: "Ana" }]
});
renderizarResultado({
  kind: "erro",
  mensagem: "Servidor indisponível"
});

Explicando o código

Cada variante da union tem uma propriedade kind que funciona como "discriminante" — ela identifica qual estado é qual. No switch, o TypeScript usa o kind para restringir quais propriedades estão disponíveis em cada caso.

Note que no caso "sucesso", temos acesso a resultado.dados, e no caso "erro", temos acesso a resultado.mensagem. Em "carregando", não há dados extras. Isso é type narrowing — o TypeScript "estreita" o tipo baseado no discriminante.

Onde é usado: Estados de requisições HTTP, fluxos de autenticação, status de uploads, resultados de validação de formulário.

satisfies — validação sem widening (TypeScript 4.9+)

O operador satisfies valida se um valor corresponde a um tipo sem alterar o tipo inferido. Diferente da anotação de tipo tradicional, ele mantém a informação literal. 

// Com anotação de tipo tradicional — o tipo é "ampliado"
type CoresMap = {
  [key: string]: [number, number, number];
};

const paleta: CoresMap = {
  vermelho: [255, 0, 0],
  verde: [0, 255, 0],
  azul: [0, 0, 255]
};
// paleta.vermelho tem tipo [number, number, number]

// Com satisfies — mantém os tipos literais
const paletaSatisfies = {
  vermelho: [255, 0, 0],
  verde: [0, 255, 0],
  azul: [0, 0, 255]
} satisfies CoresMap;
// paletaSatisfies.vermelho tem tipo [255, 0, 0] (literal!)

Explicando o código

Com : CoresMap, o TypeScript "amplia" os tipos — os arrays viram [number, number, number] genérico. Com satisfies CoresMap, o TypeScript valida que a estrutura está correta, mas mantém os valores literais: [255, 0, 0] em vez de apenas [number, number, number].

Benefício: Sua IDE mostra os valores exatos ao passar o mouse, e você ainda tem a segurança de que o objeto segue o tipo definido.

Resumo dos Conceitos

Conceito Para que serve Quando usar
if / else Tomar decisões Condições simples ou com intervalos
switch Comparar contra valores fixos Múltiplos cases com igualdade
enum Conjunto de constantes nomeadas Estados, roles, categorias fixas
const enum Enum otimizado (inline) Performance e quando não precisa de busca reversa
Union types Alternativa leve a enums Strings fixas, métodos HTTP, status simples
?? Valor padrão para null/undefined Parâmetros opcionais, configurações
?. Acesso seguro a propriedades Objetos com propriedades opcionais
as const Valores literais fixos Listas de opções sem declarar enum
Discriminated unions Estados bem definidos Requisições, fluxos, status de UI
satisfies Validação sem ampliar tipo Configurações, constantes complexas

// --- Nullish Coalescing ---
type Configuracoes = {
  tema: string | null;
  idioma: string | null;
};

const config: Configuracoes = {
  tema: null,
  idioma: "pt-BR"
};

const temaUsado = config.tema ?? "dark";
const idiomaUsado = config.idioma ?? "en";

console.log(`Idioma: ${idiomaUsado}`); // "pt-BR" (não é null → mantém)

// --- Optional Chaining ---
type Empresa = {
  nome: string;
  filial?: {
    endereco?: {
      cidade?: string;
    };
  };
};

const empresaComFilial: Empresa = {
  nome: "TechCorp",
  filial: {
    endereco: {
      cidade: "Rio de Janeiro"
    }
  }
};

const empresaSemFilial: Empresa = {
  nome: "StartupSolo"
};

console.log(empresaComFilial.filial?.endereco?.cidade); // "Rio de Janeiro"
console.log(empresaSemFilial.filial?.endereco?.cidade); // undefined (sem erro)

// --- Discriminated Union ---
type ResultadoAPI =
  | { status: "carregando" }
  | { status: "sucesso"; dados: string[] }
  | { status: "erro"; erro: string };

function processarResultado(resultado: ResultadoAPI): void {
  switch (resultado.status) {
    case "carregando":
      console.log("Buscando dados...");
      break;
    case "sucesso":
      console.log(`${resultado.dados.length} itens encontrados`);
      break;
    case "erro":
      console.log(`Falha: ${resultado.erro}`);

Sistema de Gerenciamento de Pedidos

Crie um arquivo src/pedidos.ts com um sistema completo de pedidos usando os conceitos desta aula:

  1. Crie um enum chamado StatusPedido com os valores: Novo, EmPreparo, Enviado, Entregue, Cancelado
  2. Crie um enum chamado TipoPagamento com os valores: Pix, Credito, Debito
  3. Crie uma type (union type) chamada RegiaoEnvio com os valores: "norte", "nordeste", "centro-oeste", "sudeste", "sul"
  4. Crie uma função processarPedido que receba o status e exiba uma mensagem adequada usando switch
  5. Crie uma função calcularFrete que receba a região e retorne o valor do frete (use switch ou if/else)
  6. Use nullish coalescing para tratar um campo opcional cupomDesconto: string | null
  7. Use optional chaining para acessar dados de um cliente que pode ou não ter endereço cadastrado

Obs: Não se esqueça de subir as alterações para o Git na branch dessa aula após terminar o dever.

Gabarito:

Arquivo src/pedidos.ts: 

// src/pedidos.ts

// --- Enums ---
enum StatusPedido {
  Novo = "NOVO",
  EmPreparo = "EM_PREPARO",
  Enviado = "ENVIADO",
  Entregue = "ENTREGUE",
  Cancelado = "CANCELADO"
}

enum TipoPagamento {
  Pix = "PIX",
  Credito = "CRÉDITO",
  Debito = "DÉBITO"
}

// --- Union type ---
type RegiaoEnvio = "norte" | "nordeste" | "centro-oeste" | "sudeste" | "sul";

// --- Discriminated union para resultado ---
type ResultadoPedido =
  | { ok: true; mensagem: string }
  | { ok: false; erro: string };

// --- Função com switch ---
function processarPedido(status: StatusPedido): void {
  switch (status) {
    case StatusPedido.Novo:
      console.log("Pedido registrado. Aguardando pagamento...");
      break;
    case StatusPedido.EmPreparo:
      console.log("Preparando seu pedido...");
      break;
    case StatusPedido.Enviado:
      console.log("Pedido a caminho!");
      break;
    case StatusPedido.Entregue:
      console.log("Pedido entregue com sucesso!");
      break;
    case StatusPedido.Cancelado:
      console.log("Pedido cancelado. Estorno em processamento.");
      break;
  }
}

// --- Função com if/else ---
function calcularFrete(regiao: RegiaoEnvio): number {
  if (regiao === "sudeste") {
    return 15.0;
  } else if (regiao === "sul" || regiao === "centro-oeste") {
    return 22.5;
  } else {
    return 35.0;
  }
}

// --- Nullish coalescing ---
function aplicarDesconto(valor: number, cupom: string | null): number {
  const desconto = cupom ?? "SEM_DESCONTO";
  console.log(`Cupom aplicado: ${desconto}`);
  return desconto !== "SEM_DESCONTO" ? valor * 0.9 : valor;
}

// --- Optional chaining ---
type Cliente = {
  nome: string;
  endereco?: {
    cidade?: string;
    estado?: string;
  };
};

function exibirCliente(cliente: Cliente): void {
  const cidade = cliente.endereco?.cidade ?? "Não informada";
  const estado = cliente.endereco?.estado ?? "Não informado";
  console.log(`${cliente.nome} — ${cidade}/${estado}`);
}

// --- Execução ---
processarPedido(StatusPedido.EmPreparo);
console.log(`Frete para Sul: R$ ${calcularFrete("sul")}`);
console.log(`Preço final: R$ ${aplicarDesconto(100, null)}`);

exibirCliente({ nome: "Ana", endereco: { cidade: "SP", estado: "SP" } });
exibirCliente({ nome: "Carlos" });

Explicando o código

O exercício combina todos os conceitos da aula em um único arquivo coeso. Os enums definem os estados possíveis, as union types criam restrições para regiões, e as funções usam switch e if/else para tomar decisões.

O nullish coalescing trata o cupom de desconto — se for null, usa "SEM_DESCONTO". O optional chaining acessa endereço do cliente sem risco de erro quando ele não está cadastrado.

A discriminated union ResultadoPedido mostra como definir estados bem tipados para resultados de operações — um padrão essencial em aplicações reais.
