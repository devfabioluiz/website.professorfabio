O Projeto Final

Chegou a hora de construir o nosso projeto final em TypeScript! Ele será exatamente igual ao projeto final de React — mesmas telas, mesma lógica e a mesma organização em Atomic Design —, a única diferença é que tudo será escrito em TypeScript (arquivos .ts e .tsx) em vez de JavaScript.

A lógica (login, cadastro de usuário, listagem, criação, edição e exclusão de produtos usando a API Node já publicada) continua a mesma do projeto de React — vamos apenas reescrevê-la com a segurança dos tipos do TypeScript.

  • O projeto é novo: criamos ele com o Vite, não partimos de um repositório antigo.

  • Todo componente, estado, evento, função e resposta de API recebe seu tipo.

Passo a Passo

Passo 0 — Criar o projeto React com TypeScript (Vite)

O Vite é a ferramenta de build usada atualmente na comunidade React. O template react-ts já vem com TypeScript configurado e com a pasta src cheia de arquivos .tsx prontos. Crie o projeto com o nome projeto-react-com-typescript: 

npm create vite@latest projeto-react-com-typescript -- --template react-ts
cd projeto-react-com-typescript
npm install
npm run dev

🤓 Explicando o código 📝

npm create vite@latest — cria um novo projeto com o Vite. O argumento projeto-react-com-typescript é o nome da pasta e do projeto.

-- --template react-ts — o que vem depois do -- é repassado ao Vite: o template react-ts significa React + TypeScript. É o mesmo comando da Aula 8, só mudando o nome do projeto.

cd entra na pasta, npm install instala as dependências e npm run dev sobe o servidor de desenvolvimento (normalmente em http://localhost:5173).

Extensões: .ts é arquivo TypeScript puro; .tsx é TypeScript com JSX (só React usa). O Vite não compila TypeScript sozinho — ele delega ao compilador tsc.

A estrutura que o Vite gera

projeto-react-com-typescript/
│
├── index.html
├── package.json
├── tsconfig.json
├── tsconfig.app.json
├── tsconfig.node.json
├── vite.config.ts
│
└── src/
    ├── main.tsx
    ├── App.tsx
    ├── App.css
    ├── index.css
    └── vite-env.d.ts

🤓 O que são esses arquivos? 📝

src/main.tsx — ponto de entrada da aplicação (o que o index.html carrega).

src/App.tsx — componente raiz; é nele que montamos as rotas e os componentes.

tsconfig.json e seus arquivos irmãos — configuração do compilador TypeScript. O mais importante é "strict": true, que obriga todo valor a ter tipo declarado. Veja a explicação completa na Aula 8.

vite.config.ts — configuração do próprio Vite (já está em TypeScript, como tudo no projeto).

Para conferir se o TypeScript está funcionando, rode:

# Só checa os tipos, não gera arquivo (usa o tsconfig.json)
npx tsc --noEmit

# Build de produção: roda o tsc e depois o Vite
npm run build

# Sobe o app em modo desenvolvimento
npm run dev

🤓 Explicando o código 📝

npx tsc --noEmit — valida todos os tipos do projeto e não gera nenhum arquivo. Se aparecer algum erro TS...., corrija antes de continuar.

npm run build — é o comando que a gente usa antes de subir o código: primeiro o tsc checa os tipos e depois o Vite gera a pasta dist.

Crie um repositório vazio (sem README, sem .gitignore) no GitHub chamado projeto-react-com-typescript e depois conecte o projeto local a ele: 

git init

🤓 Explicando o código 📝

git init transforma a pasta em um repositório Git local; git add . e git commit salvam o projeto criado pelo Vite.

git branch -M main garante que a branch principal se chama main e git checkout -b projeto-final cria e alterna para a branch do projeto final.

git remote add origin ... aponta para o repositório que você criou no GitHub (troque SEU-USUARIO) e git push --set-upstream origin projeto-final envia a branch e a vincula ao remoto.

🧩 PASSO 2 — ENTENDER O ATOMIC DESIGN

Atomic Design é uma metodologia criada por Brad Frost que organiza a interface em cinco níveis de complexidade, inspirados na química. Assim como a matéria é formada por átomos que se combinam em moléculas, nossas telas são formadas por pequenos componentes que se combinam em blocos maiores.

Os cinco níveis são:

  1. Átomos (Atoms) — os menores elementos da interface: botões, inputs, labels, títulos. Não podem ser divididos e não fazem sentido sozinhos.
  2. Moléculas (Molecules) — a união de dois ou mais átomos. Exemplo: um label + um input = um campo de formulário.
  3. Organismos (Organisms) — a união de várias moléculas formando uma seção completa. Exemplo: um formulário de login inteiro, ou a lista de produtos.
  4. Templates — o esqueleto da página: definem onde os organismos ficam posicionados, sem conteúdo real (layout).
  5. Páginas (Pages) — o template com o conteúdo real, ou seja, a tela que o usuário vê.

🎯 Por que usar Atomic Design?

  • Reutilização: o mesmo botão e o mesmo input são usados em várias telas.
  • Manutenção: para mudar a cor de todos os botões, alteramos um único arquivo.
  • Organização: pastas claras tornam o projeto previsível e fácil de navegar.
  • Escala: padrão muito usado em projetos profissionais de larga escala.
  • Tipagem: cada pasta tem seus próprios arquivos de tipos, deixando as interfaces de cada componente bem definidas.

🤓 Mapeando o que já fizemos 📝

No projeto de React, o componente CriarProduto.jsx da Aula 11 misturava tudo: labels, inputs, botão e a requisição. No Atomic Design ele se torna uma página (CriarProduto.tsx) que apenas compõe organismos (formulários) e moléculas (campos), que por sua vez usam átomos (botões e inputs). A lógica de negócio continua nas páginas e nos organismos — agora com tipos.

Repare que todo arquivo de componente termina em .tsx (contém JSX) e os arquivos de src/types terminam em .ts (só declaram tipos, sem JSX).

PASSO 4 — Fazer o filtro de produtos

Implemente um filtro de produtos que permita aos usuários buscar e filtrar produtos por nome na página Home, a que lista os produtos

Obs: O filtro deve ser implementado como um componente reutilizável. Além disso, você deve usar o AutoComplete do material ui.

🔎 PASSO 5 — O que precisa de tipo no projeto (apenas informação)

Esta etapa é diferente das outras: aqui não vamos mostrar como fazer. Vamos apenas informar quais partes do projeto precisam de tipos, interfaces e enums. A aplicação prática é com vocês — usem o que estudamos na Aula 8 do TypeScript como referência.

⚠️ Objetivo desta etapa

Vocês devem aplicar a tipagem por conta própria, seguindo a tabela abaixo. Nenhuma dessas implementações será dada passo a passo: o objetivo é que vocês reconheçam onde cada conceito de TypeScript se encaixa em um projeto React real.

Componentes que devem ter tipos

Onde O que deve ser tipado Conceito do TypeScript
Todos os componentes com entrada de dados (Button, Input, Label, FormField, ProductCard, Header, PageLayout) Cada propriedade recebida pelo componente Interface de props (ex.: XxxProps)
Formulários (LoginForm, RegistrarForm, ProductForm) Estado dos campos (useState), eventos de submit e change Tipos genéricos do useState<T> e tipos de evento (FormEvent, ChangeEvent)
Páginas (Home, Login, Registrar, CriarProduto, EditarProduto) Estados da tela (listagem, carregando, erro) e dados vindos da rota Union types e discriminated unions (ex.: estado da requisição)
Contexto de tema (escuro/claro) e de autenticação O valor fornecido pelo contexto e as props do provider Interfaces do contexto e generics
Botão de tema, papéis de usuário e critério de filtro/ordenação Conjuntos de valores fixos e nomeados enum (ex.: tema, papel do usuário, critério de ordenação)
Camada de API (login, cadastro, CRUD de produtos) e arquivos em src/types/ Formato de Produto, Usuario, Credenciais, token e respostas de erro Interfaces + módulos (export/import type)
Hooks customizados Parâmetros e o que o hook devolve Funções genéricas e tuples tipadas
Funções utilitárias e callbacks (onClick, onSubmit, rotas) Parâmetros, valor de retorno e retorno Promise Tipagem de funções (: void, : Promise<T>)
Acesso a elementos do DOM (useRef) O tipo real do elemento referenciado useRef<T>

🤓 Lembrete dos conceitos 📝

  • Interface — contrato do que um componente recebe; obrigatória para as props de todo componente que recebe dados (Aula 6).
  • Enum — nomes fixos para valores fixos: tema claro/escuro, papéis de usuário, critério de filtro. Evita strings soltas pelo código (Aula 2).
  • Discriminated union — estados da requisição (carregando / erro / sucesso) em um único tipo (Aula 2).
  • Generics e tuples — useState<T>, hooks que devolvem vários valores tipados (Aula 4).
  • Tipagem de eventos — saber se o evento veio de um input, de um form ou de um botão (Aula 6).
