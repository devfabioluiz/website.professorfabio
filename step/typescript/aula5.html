Funções em TypeScript

Funções são blocos de código reutilizáveis que executam uma tarefa específica. No TypeScript, funções ganham superpoderes com a tipagem — você define os tipos de entrada e saída, e o compilador garante que tudo esteja correto.

Criação de funções com tipo de retorno

// Tipo de retorno explícito (mais seguro)
export {};
function somar(a: number, b: number): number {
  return a + b;
}

// Tipo inferido (TypeScript descobre sozinho)
function multiplicar(a: number, b: number) {
  return a * b; // tipo inferido como number
}

// Sem retorno (void)
function exibirMensagem(msg: string): void {
  console.log(msg);
}

console.log(somar(5, 3));      // 8
console.log(multiplicar(4, 2)); // 8
exibirMensagem("Olá!");

Explicando o código

O tipo de retorno após os parâmetros (: number) garante que a função sempre retorne um número. Se tentarmos retornar uma string, o compilador avisa. O TypeScript também infere o tipo quando não declaramos — mas explícito é mais seguro e legível.

Parâmetros obrigatórios


export {};
function criarUsuario(nome: string, email: string, idade: number): string {
  return `Usuário: ${nome}, ${idade} anos, email: ${email}`;
}

console.log(criarUsuario("Ana", "ana@email.com", 28));
// criarUsuario("Ana", "ana@email.com"); // ERRO: falta o parâmetro idade

Parâmetros opcionais

// O "?" torna o parâmetro opcional (pode ser undefined)
export {};
function criarUsuario(nome: string, email: string, idade?: number): string {
  if (idade !== undefined) {
    return `${nome}, ${idade} anos`;
  }
  return nome;
}

console.log(criarUsuario("Ana", "ana@email.com", 28)); // "Ana, 28 anos"
console.log(criarUsuario("Bob", "bob@email.com"));     // "Bob"

Explicando o código

O ? antes do tipo indica que o parâmetro é opcional. Dentro da função, idade pode ser number ou undefined. A verificação idade !== undefined garante que só usamos o valor quando ele existe.

Parâmetros com valores padrão

// Valor padrão é usado quando o parâmetro não é passado
export {};
function criarPagina(titulo: string, idioma: string = "pt-BR"): string {
  return `Página: ${titulo} (${idioma})`;
}

console.log(criarPagina("Sobre"));           // "Página: Sobre (pt-BR)"
console.log(criarPagina("About", "en-US")); // "Página: About (en-US)"

// Valor padrão com expressão
function gerarId(prefixo: string = `ID-${Date.now()}`): string {
  return prefixo;
}

Rest parameters — múltiplos argumentos

// "..." coleta todos os argumentos extras em um array
export {};
function somarTudo(...numeros: number[]): number {
  return numeros.reduce((total, n) => total + n, 0);
}

console.log(somarTudo(10, 20, 30));     // 60
console.log(somarTudo(1, 2, 3, 4, 5)); // 15

// Rest com parâmetros obrigatórios antes
function logNivel(nivel: string, ...mensagens: string[]): void {
  console.log(`[${nivel}]`, ...mensagens);
}

logNivel("INFO", "Servidor", "iniciado", "com sucesso");
// [INFO] Servidor iniciado com sucesso

Explicando o código

O ...numeros recebe todos os argumentos adicionais como um array de numbers. Podemos passar quantos argumentos quisermos — todos serão coletados em numeros.

Regra: parâmetros com ... devem ser os últimos da lista. Parâmetros obrigatórios vêm primeiro.

Sobrecarga e Tipos de Função

Sobrecarga de funções

Permite que uma função aceite diferentes assinaturas (quantidades e tipos de parâmetros) e retorne tipos diferentes. 

// Sobrecarga: definir múltiplas assinaturas
export {};
function formatar(valor: number): string;
function formatar(valor: string): string;
function formatar(valor: number | string): string {
  if (typeof valor === "number") {
    return `R$ ${valor.toFixed(2)}`;
  }
  return valor.toUpperCase();
}

console.log(formatar(45.9));    // "R$ 45.90"
console.log(formatar("hello")); // "HELLO"

Explicando o código

As duas primeiras linhas são as assinaturas de sobrecarga — elas dizem ao TypeScript quais combinações são aceitas. A terceira linha é a implementação que trata os dois casos.

Quando usar: quando uma função pode retornar tipos diferentes dependendo da entrada. Caso contrário, prefira union types simples (string | number).

Tipo de função

// Definir um "tipo" para funções
export {};
type OperacaoMatematica = (a: number, b: number) => number;

const somar: OperacaoMatematica = (a, b) => a + b;
const subtrair: OperacaoMatematica = (a, b) => a - b;
const multiplicar: OperacaoMatematica = (a, b) => a * b;

// Função que recebe outra função como parâmetro
function calcular(a: number, b: number, operacao: OperacaoMatematica): number {
  return operacao(a, b);
}

console.log(calcular(10, 5, somar));      // 15
console.log(calcular(10, 5, subtrair));   // 5
console.log(calcular(10, 5, multiplicar)); // 50

Explicando o código

O tipo OperacaoMatematica define a "forma" de uma função: recebe dois números e retorna um número. Qualquer função que siga essa assinatura pode ser passada como argumento.

Esse padrão é fundamental para programação funcional e é usado extensivamente em métodos de array (map, filter, reduce).

Funções Anônimas e Arrow Functions

Função anônima

// Função atribuída a uma variável (sem nome)
export {};
const dobrar = function (x: number): number {
  return x * 2;
};

console.log(dobrar(5)); // 10

Arrow function

// Sintaxe curta com =>
const subtrair = (a: number, b: number): number => a - b;

// Uma linha sem chaves: retorna automaticamente
const ehPar = (n: number): boolean => n % 2 === 0;

// Com chaves: precisa de return explícito
const calcularIdade = (anoNascimento: number): number => {
  const anoAtual = 2025;
  return anoAtual - anoNascimento;
};

console.log(subtrair(10, 3));      // 7
console.log(ehPar(4));             // true
console.log(calcularIdade(1995));  // 30

Explicando o código

Arrow functions são mais curtas que funções tradicionais. Quando o corpo tem apenas uma expressão, podemos omitir as chaves {} e o return. Quando há múltiplas linhas, usamos chaves e return explícito.

Funções como parâmetros (callbacks)

// Callback tipado — padrão muito usado no dia a dia
function processarLista<T>(lista: T[], callback: (item: T) => void): void {
  for (const item of lista) {
    callback(item);
  }
}

const nomes: string[] = ["Ana", "Bob", "Carlos"];

processarLista(nomes, (nome) => {
  console.log(`Olá, ${nome}!`);
});
// Olá, Ana!
// Olá, Bob!
// Olá, Carlos!

// Outro exemplo: simular requisição
type RespostaCallback = (dados: string, erro: string | null) => void;

function buscarDados(url: string, callback: RespostaCallback): void {
  // Simulando uma resposta
  callback(`Dados de ${url}`, null);
}

buscarDados("/api/usuarios", (dados, erro) => {
  if (erro) {
    console.log(`Erro: ${erro}`);
  } else {
    console.log(dados); // "Dados de /api/usuarios"
  }
});

Explicando o código

O padrão de callback é quando uma função recebe outra função como argumento e a chama em algum momento. É a base de programação assíncrona, eventos e métodos de array.

Note o tipo do callback: (item: T) => void — recebe um item e não retorna nada. O TypeScript valida que o callback passado tenha essa assinatura.

Closures

Uma closure é uma função que "lembra" do escopo onde foi criada, mesmo após esse escopo ter terminado. Ela captura as variáveis externas e pode usá-las depois. 

// Exemplo 1: Contador
function criarContador(): () => number {
  let count: number = 0; // variável do escopo externo

  return () => {
    count++; // a função "lembra" de count
    return count;
  };
}

const contador = criarContador();
console.log(contador()); // 1
console.log(contador()); // 2
console.log(contador()); // 3

// Exemplo 2: Cache simples
function criarCache<T>(fn: (key: string) => T): (key: string) => T {
  const cache = new Map<string, T>();

  return (key: string): T => {
    if (cache.has(key)) {
      console.log(`Cache HIT: ${key}`);
      return cache.get(key)!;
    }

    console.log(`Cache MISS: ${key}`);
    const resultado = fn(key);
    cache.set(key, resultado);
    return resultado;
  };
}

const buscaComCache = criarCache((key: string) => {
  console.log(`Buscando ${key}...`);
  return `Dados de ${key}`;
});

console.log(buscaComCache("usuarios")); // Cache MISS + busca
console.log(buscaComCache("usuarios")); // Cache HIT (sem buscar)

Explicando o código

No exemplo do contador, a variável count existe dentro de criarContador. Quando a função retorna, normalmente essas variáveis seriam destruídas. Mas a closure mantém count "viva" — cada chamada ao contador incrementa o mesmo valor.

O cache é um padrão real: a closure armazena os dados no Map e reutiliza resultados anteriores. É como criar uma "memória" encapsulada.

Funções Assíncronas com async/await

Funções assíncronas retornam Promise. O TypeScript permite tipar o valor que a Promise resolve. 

// Promise tipada: Promise<tipo do resolve>
function buscarUsuario(id: number): Promise<string> {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve(`Usuário #${id}`);
    }, 1000);
  });
}

// async/await — forma moderna de trabalhar com Promises
async function listarUsuarios(): Promise<void> {
  console.log("Buscando...");

  const usuario1 = await buscarUsuario(1);
  console.log(usuario1); // "Usuário #1"

  const usuario2 = await buscarUsuario(2);
  console.log(usuario2); // "Usuário #2"

  console.log("Pronto!");
}

listarUsuarios();

// Promise.all — buscar vários ao mesmo tempo
async function buscarTodos(): Promise<string[]> {
  const resultados = await Promise.all([
    buscarUsuario(1),
    buscarUsuario(2),
    buscarUsuario(3)
  ]);

  return resultados;
}

buscarTodos().then(r => console.log(r));

Explicando o código

Promise<string> diz que a Promise vai resolver com um valor do tipo string. Quando usamos await, o TypeScript "desempacota" a Promise e nos dá o valor diretamente.

async function é obrigatório para usar await dentro de uma função. O tipo de retorno é sempre Promise<T>.

Funções Genéricas

Funções genéricas funcionam com qualquer tipo — o tipo é definido quando a função é chamada. Veja a diferença: 

// SEM generics — usa any (perde segurança)
function primeiroAny(arr: any[]): any {
  return arr[0];
}

// COM generics — tipo é preservado
function primeiro<T>(arr: T[]): T {
  return arr[0];
}

const nome = primeiro(["Ana", "João"]);   // tipo: string
const nota = primeiro([7.5, 8.0, 9.2]);   // tipo: number

console.log(nome.toUpperCase()); // OK: TypeScript sabe que é string
// console.log(nota.toUpperCase()); // ERRO: number não tem toUpperCase

Explicando o código

O T é um "placeholder" que só será definido quando chamarmos a função. Se passarmos ["Ana", "João"], o T vira string. O TypeScript infere automaticamente — não precisamos declarar.

Função genérica com constraint

// T deve ter uma propriedade "id"
function buscarPorId<T extends { id: number }>(lista: T[], id: number): T | undefined {
  return lista.find(item => item.id === id);
}

type Usuario = { id: number; nome: string; email: string };
type Produto = { id: number; nome: string; preco: number };

const usuarios: Usuario[] = [
  { id: 1, nome: "Ana", email: "ana@email.com" },
  { id: 2, nome: "Bob", email: "bob@email.com" }
];

const produtos: Produto[] = [
  { id: 1, nome: "Notebook", preco: 3500 },
  { id: 2, nome: "Mouse", preco: 89 }
];

buscarPorId(usuarios, 1); // OK: Usuario tem id
buscarPorId(produtos, 2); // OK: Produto tem id
// buscarPorId([1, 2, 3], 1); // ERRO: number não tem id

Função genérica com múltiplos tipos

// Dois tipos genéricos: T e U
function combinar<T, U>(chave: T, valor: U): { [K in string]: U } {
  return { [chave as string]: valor };
}

const resultado = combinar("nome", "Ana");
console.log(resultado); // { nome: "Ana" }

// Função que agrupa por propriedade
function agruparPor<T, K extends keyof T>(lista: T[], propriedade: K): Map<T[K], T[]> {
  const mapa = new Map<T[K], T[]>();

  for (const item of lista) {
    const chave = item[propriedade];
    if (!mapa.has(chave)) {
      mapa.set(chave, []);
    }
    mapa.get(chave)!.push(item);
  }

  return mapa;
}

type Produto = { nome: string; categoria: string; preco: number };

const produtos: Produto[] = [
  { nome: "Notebook", categoria: "TI", preco: 3500 },
  { nome: "Mouse", categoria: "TI", preco: 89 },
  { nome: "Cadeira", categoria: "Móvel", preco: 450 }
];

const porCategoria = agruparPor(produtos, "categoria");
console.log(porCategoria.get("TI")); // [Notebook, Mouse]

Explicando o código

A função agruparPor usa keyof T para garantir que a propriedade passada existe no tipo T. Se tentarmos passar "cor" para um array de Produto, o TypeScript gera erro — porque Produto não tem propriedade cor.

Exemplo integrador: função genérica de busca em API

type Resultado<T> =
  | { ok: true; dados: T }
  | { ok: false; erro: string };

async function buscarAPI<T>(url: string): Promise<Resultado<T>> {
  try {
    const response = await fetch(url);

    if (!response.ok) {
      return { ok: false, erro: `HTTP ${response.status}` };
    }

    const dados: T = await response.json();
    return { ok: true, dados };
  } catch (error) {
    return { ok: false, erro: "Falha na conexão" };
  }
}

// Uso com tipo específico
type Usuario = { id: number; nome: string };

async function carregarUsuarios() {
  const resultado = await buscarAPI<Usuario[]>("/api/usuarios");

  if (resultado.ok) {
    console.log(`${resultado.dados.length} usuários encontrados`);
  } else {
    console.log(`Erro: ${resultado.erro}`);
  }
}

Explicando o código

Esta função combina async/await, generics e discriminated unions — tudo que vimos nas aulas anteriores. Ela funciona para qualquer tipo de dados da API, e o TypeScript garante que, quando resultado.ok for true, temos acesso a resultado.dados.

// src/utilitarios.ts

// 1. Agrupar por propriedade
function agruparPor<T, K extends keyof T>(lista: T[], prop: K): Map<T[K], T[]> {
  const mapa = new Map<T[K], T[]>();
  for (const item of lista) {
    const chave = item[prop];
    if (!mapa.has(chave)) {
      mapa.set(chave, []);
    }
    mapa.get(chave)!.push(item);
  }
  return mapa;
}

// 2. Ordenar por propriedade numérica
function ordenarPor<T, K extends keyof T>(lista: T[], prop: K): T[] {
  return [...lista].sort((a, b) => {
    const valA = a[prop] as unknown as number;
    const valB = b[prop] as unknown as number;
    return valA - valB;
  });
}

// 3. Buscar maior
function buscarMaior<T, K extends keyof T>(lista: T[], prop: K): T {
  return lista.reduce((maior, item) => {
    const valAtual = item[prop] as unknown as number;
    const valMaior = maior[prop] as unknown as number;
    return valAtual > valMaior ? item : maior;
  });
}

// 4. Cache de função
function cacheFn<T, R>(fn: (arg: T) => R): (arg: T) => R {
  const cache = new Map<T, R>();
  return (arg: T): R => {
    if (cache.has(arg)) return cache.get(arg)!;
    const resultado = fn(arg);
    cache.set(arg, resultado);
    return resultado;
  };
}

Todas usam extends keyof T para garantir que a propriedade passada existe no tipo — segurança de tipos sem perder flexibilidade.
