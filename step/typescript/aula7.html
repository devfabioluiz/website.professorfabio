Herança em TypeScript

Herança permite que uma classe filha reutilize propriedades e métodos de uma classe pai. É um dos pilares da POO — evita código duplicado e cria hierarquias naturais.

extends e super()

class Animal {
  constructor(
    public nome: string,
    public especie: string
  ) {}

  descrever(): string {
    return `${this.nome} é um ${this.especie}`;
  }
}

class Cachorro extends Animal {
  constructor(
    nome: string,
    public raca: string
  ) {
    super(nome, "cachorro"); // chama o constructor da classe pai
  }

  latir(): void {
    console.log(`${this.nome} diz: Au au!`);
  }

  descrever(): string {
    // Usando super para acessar o método do pai
    return `${super.descrever()} da raça ${this.raca}`;
  }
}

const rex = new Cachorro("Rex", "Labrador");
rex.latir();                    // "Rex diz: Au au!"
console.log(rex.descrever());   // "Rex é um cachorro da raça Labrador"

Explicando o código

extends Animal faz Cachorro herdar todas as propriedades e métodos de Animal. O super(nome, "cachorro") chama o construtor do pai, passando os parâmetros que ele espera.

O método descrever() é sobrescrito na classe filha — ele tem o mesmo nome mas um comportamento diferente. super.descrever() permite reutilizar a lógica do pai dentro da sobrescrita.

Construtores na herança

class Veiculo {
  constructor(
    public marca: string,
    public modelo: string,
    public ano: number
  ) {}

  getDetails(): string {
    return `${this.ano} ${this.marca} ${this.modelo}`;
  }
}

class Carro extends Veiculo {
  constructor(
    marca: string,
    modelo: string,
    ano: number,
    public portas: number,
    public motor: string
  ) {
    super(marca, modelo, ano); // Obrigatório antes de usar "this"
  }

  override getDetails(): string {
    return `${super.getDetails()} — ${this.portas} portas, motor ${this.motor}`;
  }
}

class Moto extends Veiculo {
  constructor(
    marca: string,
    modelo: string,
    ano: number,
    public cilindradas: number
  ) {
    super(marca, modelo, ano);
  }

  override getDetails(): string {
    return `${super.getDetails()} — ${this.cilindradas}cc`;
  }
}

const meuCarro = new Carro("Toyota", "Corolla", 2022, 4, "2.0");
const minhaMoto = new Moto("Honda", "CBR", 2023, 600);

console.log(meuCarro.getDetails());
// 2022 Toyota Corolla — 4 portas, motor 2.0

console.log(minhaMoto.getDetails());
// 2023 Honda CBR — 600cc

Explicando o código

O construtor da classe filha deve chamar super() antes de usar this. Isso garante que as propriedades da classe pai sejam inicializadas primeiro.

Note que Carro tem propriedades extras (portas, motor) e Moto tem cilindradas. Cada classe especializa o comportamento do pai.

Herança de interfaces

interface Funcionario {
  nome: string;
  salario: number;
  calcularBonus(): number;
}

// Estendendo interface
interface Gerente extends Funcionario {
  departamento: string;
  numSubordinados: number;
}

// Múltipla herança de interfaces
interface Estagiario extends Funcionario {
  duracaoContrato: number;
  universidade: string;
}

const ana: Gerente = {
  nome: "Ana",
  salario: 10000,
  calcularBonus() { return this.salario * 0.2; },
  departamento: "TI",
  numSubordinados: 5
};

const bob: Estagiario = {
  nome: "Bob",
  salario: 2000,
  calcularBonus() { return this.salario * 0.05; },
  duracaoContrato: 12,
  universidade: "USP"
};

Polimorfismo

Polimorfismo significa "muitas formas" — objetos de classes diferentes podem ser tratados pela mesma interface, mas cada um responde de forma diferente. É o que torna o código flexível e extensível.

Polimorfismo com herança

class FormaGeometrica {
  constructor(public nome: string) {}

  calcularArea(): number {
    return 0;
  }
}

class Circulo extends FormaGeometrica {
  constructor(public raio: number) {
    super("Círculo");
  }

  override calcularArea(): number {
    return Math.PI * this.raio ** 2;
  }
}

class Retangulo extends FormaGeometrica {
  constructor(public largura: number, public altura: number) {
    super("Retângulo");
  }

  override calcularArea(): number {
    return this.largura * this.altura;
  }
}

class Triangulo extends FormaGeometrica {
  constructor(public base: number, public altura: number) {
    super("Triângulo");
  }

  override calcularArea(): number {
    return (this.base * this.altura) / 2;
  }
}

// Mesma função, diferentes comportamentos
function imprimirArea(forma: FormaGeometrica): void {
  console.log(`${forma.nome}: ${forma.calcularArea().toFixed(2)}`);
}

imprimirArea(new Circulo(5));          // Círculo: 78.54
imprimirArea(new Retangulo(4, 6));     // Retângulo: 24.00
imprimirArea(new Triangulo(10, 8));    // Triângulo: 40.00

Explicando o código

A função imprimirArea recebe um FormaGeometrica, mas na verdade pode receber qualquer subclasse. Cada forma calcula sua área de forma diferente — o TypeScript chama o método correto em tempo de execução. Isso é polimorfismo: uma interface, múltiplos comportamentos.

instanceof — verificar tipo em runtime

function processarAnimal(animal: Animal): void {
  // Verificar o tipo exato do objeto
  if (animal instanceof Cachorro) {
    animal.latir(); // TypeScript SABE que é Cachorro aqui
    console.log(`Raça: ${animal.raca}`);
  } else if (animal instanceof Gato) {
    animal.miar(); // TypeScript SABE que é Gato aqui
  } else {
    console.log(animal.descrever());
  }
}

class Gato extends Animal {
  constructor(nome: string) {
    super(nome, "gato");
  }

  miar(): void {
    console.log(`${this.nome} diz: Miau!`);
  }
}

processarAnimal(new Cachorro("Rex", "Labrador"));
// Rex diz: Au au!
// Raça: Labrador

processarAnimal(new Gato("Mimi"));
// Mimi diz: Miau!

Explicando o código

O instanceof verifica se um objeto é instância de uma classe específica. Dentro do bloco if, o TypeScript faz type narrowing — "estreita" o tipo para que possamos acessar propriedades e métodos específicos daquela classe.

Polimorfismo com interfaces — o mais poderoso

// Interface que define um contrato de pagamento
interface MetodoPagamento {
  pagar(valor: number): boolean;
  getDescricao(): string;
}

// Cada forma de pagamento implementa a interface
class Pix implements MetodoPagamento {
  constructor(private chave: string) {}

  pagar(valor: number): boolean {
    console.log(`PIX: Pagando R$ ${valor} para ${this.chave}`);
    return true;
  }

  getDescricao(): string {
    return `PIX (${this.chave})`;
  }
}

class CartaoCredito implements MetodoPagamento {
  constructor(private numero: string, private parcelas: number = 1) {}

  pagar(valor: number): boolean {
    const valorParcela = valor / this.parcelas;
    console.log(`Crédito: ${this.parcelas}x de R$ ${valorParcela.toFixed(2)}`);
    return true;
  }

  getDescricao(): string {
    return `Cartão de crédito (final ${this.numero.slice(-4)})`;
  }
}

class Boleto implements MetodoPagamento {
  pagar(valor: number): boolean {
    console.log(`Boleto: R$ ${valor} — pagamento à vista`);
    return true;
  }

  getDescricao(): string {
    return "Boleto bancário";
  }
}

// Função que aceita QUALQUER método de pagamento
function checkout(valor: number, metodo: MetodoPagamento): void {
  console.log(`\n--- Checkout ---`);
  console.log(`Método: ${metodo.getDescricao()}`);
  metodo.pagar(valor);
  console.log("Pedido confirmado!");
}

// Polimorfismo em ação
checkout(150, new Pix("ana@email.com"));
checkout(300, new CartaoCredito("4111111111111234", 3));
checkout(80, new Boleto());

Explicando o código

A função checkout recebe qualquer objeto que implemente MetodoPagamento. Não importa se é Pix, Cartão ou Boleto — cada um paga de forma diferente, mas a função não precisa saber disso.

Esse é o poder do polimorfismo com interfaces: você pode adicionar novas formas de pagamento (PayPal, criptomoeda, etc.) sem modificar a função checkout. Basta criar uma nova classe que implemente a interface.

Resumo de POO em TypeScript

Conceitos das aulas 6 e 7

Conceito O que é Quando usar
Classe Molde para criar objetos Quando precisa de múltiplas instâncias com mesma estrutura
Construtor Inicializa propriedades ao criar objeto Sempre que a classe precisa de dados iniciais
Modificadores Controlam acesso (public/private/protected/readonly) Para proteger dados e definir visibilidade
Getters/Setters Controlam leitura/escrita de propriedades Quando precisa de validação ou lógica no acesso
Static Membros compartilhados entre instâncias Contadores, fábricas, utilitários da classe
Interface Define estrutura/contrato Para tipar objetos e criar contratos
Classe Abstrata Base para subclasses (não instanciável) Quando precisa compartilhar implementação
Herança Classe filha reutiliza código do pai Hierarquias naturais (Animal → Cachorro)
Polimorfismo Objetos diferentes respondem da mesma forma Sistemas extensíveis (pagamentos, formas, etc.)

Herança vs Composição

Herança ("é um") Composição ("tem um")
Cachorro é um Animal Carro tem um Motor
Cria hierarquias fortes Cria relações flexíveis
Acoplamento forte entre classes Baixo acoplamento
Use quando: relação natural de herança Use quando: quer flexibilidade e reuso

Sistema de Formas Geométricas com Polimorfismo

Crie um arquivo src/formas.ts que use herança e polimorfismo:

  1. Crie uma classe abstrata Forma com: nome, calcularArea(), calcularPerimetro(), descrever()
  2. Crie subclasses: Circulo, Retangulo, Triangulo
  3. Crie uma interface Colorido com propriedade cor e método pintar()
  4. Faça pelo menos uma classe implementar ambas (Forma e Colorido)
  5. Crie um array de Forma[] e itere imprimindo área, perímetro e descrição de cada uma

Obs: Não se esqueça de subir as alterações para o Git na branch dessa aula após terminar o dever.

Gabarito:

Arquivo src/formas.ts:

// src/formas.ts

// --- Classe abstrata ---
abstract class Forma {
  constructor(public nome: string) {}

  abstract calcularArea(): number;
  abstract calcularPerimetro(): number;

  descrever(): string {
    return `${this.nome}: Área=${this.calcularArea().toFixed(2)}, Perímetro=${this.calcularPerimetro().toFixed(2)}`;
  }
}

// --- Interface Colorido ---
interface Colorido {
  cor: string;
  pintar(): void;
}

// --- Subclasses ---
class Circulo extends Forma {
  constructor(public raio: number) {
    super("Círculo");
  }

  calcularArea(): number {
    return Math.PI * this.raio ** 2;
  }

  calcularPerimetro(): number {
    return 2 * Math.PI * this.raio;
  }
}

class Retangulo extends Forma implements Colorido {
  cor: string;

  constructor(
    public largura: number,
    public altura: number,
    cor: string = "sem cor"
  ) {
    super("Retângulo");
    this.cor = cor;
  }

  calcularArea(): number {
    return this.largura * this.altura;
  }

  calcularPerimetro(): number {
    return 2 * (this.largura + this.altura);
  }

  pintar(): void {
    console.log(`Retângulo pintado de ${this.cor}`);
  }
}

class Triangulo extends Forma {
  constructor(public base: number, public altura: number) {
    super("Triângulo");
  }

  calcularArea(): number {
    return (this.base * this.altura) / 2;
  }

  calcularPerimetro(): number {
    // Triângulo equilátero para simplificar
    return this.base * 3;
  }
}

// --- Polimorfismo em ação ---
const formas: Forma[] = [
  new Circulo(5),
  new Retangulo(4, 6, "azul"),
  new Triangulo(10, 8)
];

console.log("=== Relatório de Formas ===");
for (const forma of formas) {
  console.log(forma.descrever());
}

// Verificar se é Colorido
for (const forma of formas) {
  if ("pintar" in forma) {
    (forma as Colorido).pintar();
  }
}

Explicando o código

O array formas contém diferentes subclasses de Forma. Quando chamamos forma.descrever(), cada subclasse retorna uma descrição diferente — polimorfismo em ação.

A verificação "pintar" in forma detecta se o objeto implementa a interface Colorido. O as Colorido faz o type casting para acessar o método. Isso permite que formas coloridas sejam pintadas, enquanto as sem essa interface simplesmente são ignoradas.
