Classes em TypeScript

Uma classe é um molde para criar objetos. Ela define propriedades (dados) e métodos (comportamentos). No TypeScript, classes ganham tipos, modificadores de acesso e outros recursos que não existem no JavaScript puro.

Construtor e propriedades

class ContaBancaria {
  // Propriedades declaradas com modificadores no constructor
  constructor(
    public titular: string,
    private saldo: number
  ) {}

  // Método público
  depositar(valor: number): void {
    if (valor > 0) {
      this.saldo += valor;
      console.log(`Depositado: R$ ${valor}`);
    }
  }

  // Método público
  getSaldo(): number {
    return this.saldo;
  }
}

const conta = new ContaBancaria("Ana", 1000);
conta.depositar(500);
console.log(`Saldo: R$ ${conta.getSaldo()}`); // 1500
// console.log(conta.saldo); // ERRO: saldo é private

Explicando o código

O constructor é chamado quando criamos um novo objeto com new. Colocar public titular e private saldo como parâmetros do constructor cria as propriedades automaticamente — não precisamos declarar separadamente.

private saldo significa que só a própria classe pode acessar e modificar o saldo. Quem usar a classe só consegue interagir com depositar() e getSaldo().

class Funcionario {
  public nome: string;           // acessível por todos
  protected departamento: string; // acessível por subclasses
  private salario: number;        // acessível só pela classe
  readonly id: number;            // acessível por todos, mas não modifica

  constructor(nome: string, departamento: string, salario: number, id: number) {
    this.nome = nome;
    this.departamento = departamento;
    this.salario = salario;
    this.id = id;
  }

  // Só pode ser acessado dentro da classe
  private calcularBonus(): number {
    return this.salario * 0.1;
  }

  public getResumo(): string {
    return `${this.nome} (${this.departamento}) — Bônus: R$ ${this.calcularBonus()}`;
  }
}

Explicando o código

private restringe o acesso à própria classe. protected permite acesso em subclasses (herança). readonly permite leitura mas impede modificação após a construção.

Getters e Setters

class Temperature {
  private _celsius: number;

  constructor(celsius: number) {
    this._celsius = celsius;
  }

  // Getter: acessado como propriedade (sem parênteses)
  get fahrenheit(): number {
    return this._celsius * 1.8 + 32;
  }

  // Setter: atribuído como propriedade
  set celsius(valor: number) {
    if (valor < -273.15) {
      console.log("Temperatura abaixo do zero absoluto!");
      return;
    }
    this._celsius = valor;
  }

  get celsius(): number {
    return this._celsius;
  }
}

const temp = new Temperature(25);
console.log(temp.celsius);    // 25 (getter)
console.log(temp.fahrenheit); // 77 (getter calculado)

temp.celsius = 30;             // setter com validação
console.log(temp.fahrenheit); // 86

temp.celsius = -300;           // "Temperatura abaixo do zero absoluto!"

Explicando o código

Getters e setters permitem controlar acesso a propriedades como se fossem atributos normais (temp.fahrenheit), mas com lógica por trás. O setter valida o valor antes de atribuir — um padrão essencial para manter a integridade dos dados.

Propriedades e métodos estáticos

class Contador {
  // Propriedade estática — compartilhada entre todas as instâncias
  static totalInstancias: number = 0;

  public id: number;

  constructor() {
    Contador.totalInstancias++;
    this.id = Contador.totalInstancias;
  }

  // Método estáticp — chamado na classe, não na instância
  static obterTotal(): number {
    return Contador.totalInstancias;
  }
}

const c1 = new Contador();
const c2 = new Contador();
const c3 = new Contador();

console.log(c1.id);              // 1
console.log(c3.id);              // 3
console.log(Contador.obterTotal()); // 3

Explicando o código

Membros static pertencem à classe, não às instâncias. Contador.totalInstancias é único para todas as instâncias — é como uma "variável global" encapsulada na classe.

Exemplo completo: Conta Bancária

class ContaBancaria {
  private _saldo: number;
  private _historico: string[] = [];
  static totalContas: number = 0;

  constructor(
    public readonly titular: string,
    saldoInicial: number
  ) {
    this._saldo = saldoInicial;
    ContaBancaria.totalContas++;
    this.registrar(`Conta criada com saldo R$ ${saldoInicial}`);
  }

  get saldo(): number {
    return this._saldo;
  }

  depositar(valor: number): void {
    if (valor <= 0) {
      console.log("Valor deve ser positivo.");
      return;
    }
    this._saldo += valor;
    this.registrar(`Depósito: R$ ${valor}`);
  }

  sacar(valor: number): boolean {
    if (valor > this._saldo) {
      console.log("Saldo insuficiente.");
      return false;
    }
    this._saldo -= valor;
    this.registrar(`Saque: R$ ${valor}`);
    return true;
  }

  transferir(destino: ContaBancaria, valor: number): boolean {
    if (this.sacar(valor)) {
      destino.depositar(valor);
      this.registrar(`Transferência de R$ ${valor} para ${destino.titular}`);
      return true;
    }
    return false;
  }

  private registrar(mensagem: string): void {
    this._historico.push(mensagem);
  }

  getHistorico(): string[] {
    return [...this._historico];
  }

  static getTotalContas(): number {
    return ContaBancaria.totalContas;
  }
}

const ana = new ContaBancaria("Ana", 1000);
const bob = new ContaBancaria("Bob", 500);

ana.depositar(300);
ana.sacar(200);
ana.transferir(bob, 500);

console.log(`Saldo Ana: R$ ${ana.saldo}`);    // 600
console.log(`Saldo Bob: R$ ${bob.saldo}`);    // 1000
console.log(`Total de contas: ${ContaBancaria.getTotalContas()}`); // 2
console.log("Histórico Ana:", ana.getHistorico());

Interfaces

Interfaces definem a estrutura que um objeto deve seguir. No TypeScript, elas são usadas para tipagem — o compilador verifica se um objeto "obedece" à interface.

Interface básica

interface Produto {
  id: number;
  nome: string;
  preco: number;
}

// Função que recebe qualquer objeto que tenha id, nome e preco
function exibirProduto(p: Produto): void {
  console.log(`${p.nome}: R$ ${p.preco}`);
}

// Funciona — tem id, nome e preco
exibirProduto({ id: 1, nome: "Notebook", preco: 3500 });

// Funciona — tem propriedades extras (ok!)
exibirProduto({ id: 2, nome: "Mouse", preco: 89, categoria: "TI" });

// ERRO — falta "preco"
// exibirProduto({ id: 3, nome: "Teclado" });

Explicando o código

Interfaces definem um "contrato" — o objeto precisa ter no mínimo as propriedades declaradas. Propriedades extras são aceitas (isso é a tipagem estrutural do TypeScript). O que não pode é faltar uma propriedade ou ter o tipo errado.

Tipagem Estrutural (Structural Typing)

Essa é a grande diferença do TypeScript para outras linguagens. Em Java ou C#, um objeto precisa declarar explicitamente que implementa uma interface. No TypeScript, basta ter a estrutura correta — não precisa de implements. 

interface Ponto {
  x: number;
  y: number;
}

// Esta função aceita QUALQUER objeto com x e y
function distancia(p: Ponto): number {
  return Math.sqrt(p.x ** 2 + p.y ** 2);
}

// Funciona: objeto literal
console.log(distancia({ x: 3, y: 4 })); // 5

// Funciona: objeto com propriedades extras
const meuPonto = { x: 3, y: 4, cor: "vermelho" };
console.log(distancia(meuPonto)); // 5

// Funciona: outro objeto, mesma estrutura
class Coordenada {
  constructor(public x: number, public y: number) {}
}

console.log(distancia(new Coordenada(3, 4))); // 5

Explicando o código

A função distancia aceita qualquer objeto que tenha x e y como números — não importa se é um literal, uma classe, ou um objeto com propriedades extras. Isso é tipagem estrutural: o tipo é definido pela forma, não pela declaração.

Propriedades opcionais e readonly

interface Configuracao {
  readonly host: string;       // não pode ser alterado

Interface para função e interface híbrida

// Interface para função
interface Comparador<T> {
  (a: T, b: T): number;
}

const compararNumeros: Comparador<number> = (a, b) => a - b;
const compararStrings: Comparador<string> = (a, b) => a.localeCompare(b);

console.log([3, 1, 2].sort(compararNumeros)); // [1, 2, 3]
console.log(["banana", "abacaxi"].sort(compararStrings)); // ["abacaxi", "banana"]

// Interface híbrida: função com propriedades
interface Logger {
  (mensagem: string): void;
  nivel: string;
  timestamp: boolean;
}

function criarLogger(nivel: string): Logger {
  const log = ((msg: string) => {
    const prefixo = nivel.toUpperCase();
    console.log(`[${prefixo}] ${msg}`);
  }) as Logger;

  log.nivel = nivel;
  log.timestamp = true;
  return log;
}

const logger = criarLogger("info");
logger("Servidor iniciado"); // [INFO] Servidor iniciado
console.log(logger.nivel);   // "info"

Explicando o código

Uma interface híbrida define tanto a assinatura de uma função quanto propriedades. É usada em bibliotecas como jQuery e Express.js onde a mesma entidade é chamada como função e também tem propriedades.

Classes Abstratas

Uma classe abstract não pode ser instanciada diretamente. Ela serve como base para outras classes. Métodos abstratos são declarados sem implementação — cada subclasse deve implementá-los. 

// Classe abstrata — não pode fazer "new FormaGeometrica()"
abstract class FormaGeometrica {
  constructor(public nome: string) {}

  // Método abstrato — cada subclasse DEVE implementar
  abstract calcularArea(): number;
  abstract calcularPerimetro(): number;

  // Método concreto — herda normalmente
  describer(): string {
    return `${this.nome} — Área: ${this.calcularArea()}, Perímetro: ${this.calcularPerimetro()}`;
  }
}

class Circulo extends FormaGeometrica {
  constructor(public raio: number) {
    super("Círculo");
  }

  calcularArea(): number {
    return Math.PI * this.raio ** 2;
  }

  calcularPerimetro(): number {
    return 2 * Math.PI * this.raio;
  }
}

class Retangulo extends FormaGeometrica {
  constructor(public largura: number, public altura: number) {
    super("Retângulo");
  }

  calcularArea(): number {
    return this.largura * this.altura;
  }

  calcularPerimetro(): number {
    return 2 * (this.largura + this.altura);
  }
}

const circulo = new Circulo(5);
const retangulo = new Retangulo(4, 6);

console.log(circulo.describer());
// Círculo — Área: 78.54, Perímetro: 31.42

console.log(retangulo.describer());
// Retângulo — Área: 24, Perímetro: 20

Explicando o código

A classe abstrata define um contrato: qualquer classe que herdar de FormaGeometrica é obrigada a implementar calcularArea() e calcularPerimetro().

O método describer() é concreto — ele é herdado normalmente pelas subclasses. As subclasses podem usar métodos abstratos sem precisar redeclará-los.

Classe abstrata vs Interface

Classe Abstrata Interface
Pode ter construtores Não pode
Pode ter propriedades com valores Só declaração de tipo
Pode ter métodos concretos Só assinaturas
Herança única (extends) Múltipla (implements A, B)
Gera código JavaScript Removida na compilação
Use quando: compartilhar implementação Use quando: definir contrato puro

Sistema de Funcionários

Crie um arquivo src/funcionarios.ts que use classes, interfaces e classes abstratas:

  1. Crie uma interface IFuncionario com: nome, salario, calcularBonus()
  2. Crie uma classe abstrata Funcionario que implemente IFuncionario
  3. Crie subclasses Gerente e Desenvolvedor com cálculos de bônus diferentes
  4. Crie um array de IFuncionario e itere calculando o bônus de cada um (polimorfismo)

Gabarito:

Arquivo src/funcionarios.ts:

// src/funcionarios.ts

interface IFuncionario {
  nome: string;
  salario: number;
  calcularBonus(): number;
}

abstract class Funcionario implements IFuncionario {
  constructor(
    public nome: string,
    public salario: number
  ) {}

  abstract calcularBonus(): number;

  getResumo(): string {
    return `${this.nome} — Salário: R$ ${this.salario}, Bônus: R$ ${this.calcularBonus()}`;
  }
}

class Gerente extends Funcionario {
  calcularBonus(): number {
    return this.salario * 0.2; // 20%
  }
}

class Desenvolvedor extends Funcionario {
  calcularBonus(): number {
    return this.salario * 0.1; // 10%
  }
}

const equipe: IFuncionario[] = [
  new Gerente("Ana", 10000),
  new Desenvolvedor("Bob", 6000),
  new Desenvolvedor("Carlos", 7000)
];

console.log("=== Relatório de Bônus ===");
for (const func of equipe) {
  console.log(`${func.nome}: R$ ${func.calcularBonus()}`);
}

const totalBonus = equipe.reduce((soma, f) => soma + f.calcularBonus(), 0);
console.log(`Total de bônus: R$ ${totalBonus}`);

Explicando o código

O array equipe tem tipo IFuncionario[] — ele aceita qualquer classe que implemente a interface. Quando iteramos com for...of, cada funcionário calcula seu bônus de forma diferente (polimorfismo).

A classe abstrata Funcionario implementa o construtor e o método getResumo(), mas delega o cálculo do bônus para cada subclasse. Isso é o princípio de substituição de Liskov — cada subclasse pode ser usada no lugar da classe pai.
