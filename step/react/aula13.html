Autenticação vs Autorização

Autenticação responde à pergunta "quem é você?" — é o processo de verificar a identidade do usuário (login/senha). Já a Autorização responde "o que você pode fazer?" — é o controle do que um usuário autenticado tem permissão de acessar ou executar, baseado na sua função/papel (role).

A técnica de associar permissões a papéis se chama RBAC (Role-Based Access Control). Nela, definimos papéis (ex: admin, employee) e cada papel tem um conjunto de permissões.

2ª Parte — Criar o AuthContext

Crie o arquivo src/context/AuthContext.jsx. Ele deve guardar o usuário logado (com nome, email e role), persistir esse usuário no localStorage e expor as funções login e logout, além do hook useAuth.

Gabarito: 

import { createContext, useContext, useState, useEffect } from 'react';

const AuthContext = createContext();

export const AuthProvider = ({ children }) => {
  const [user, setUser] = useState(() => {
    const salvo = localStorage.getItem('usuario-logado');
    return salvo ? JSON.parse(salvo) : null;
  });

  useEffect(() => {
    if (user) {
      localStorage.setItem('usuario-logado', JSON.stringify(user));
    } else {
      localStorage.removeItem('usuario-logado');
    }
  }, [user]);

  const login = (usuario) => setUser(usuario);
  const logout = () => setUser(null);

  return (
    <AuthContext.Provider value={{ user, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
};

export const useAuth = () => useContext(AuthContext);

🤓 Explicando o código 📝

O estado user é inicializado lendo o localStorage (assim o usuário continua logado ao recarregar a página). O useEffect salva o usuário no localStorage sempre que ele muda, ou remove quando é null. O hook customizado useAuth encapsula useContext(AuthContext).

4ª Parte — Criar o ProtectedRoute

Crie o componente src/components/ProtectedRoute.jsx. Ele deve receber uma prop role e os children: se o usuário não estiver logado, redireciona para /login; se estiver logado mas sem o papel necessário, redireciona para /; caso contrário, renderiza os children.

Gabarito: 

import { Navigate } from 'react-router-dom';
import { useAuth } from '../context/AuthContext';

const ProtectedRoute = ({ role, children }) => {
  const { user } = useAuth();

  if (!user) {
    return <Navigate to="/login" />;
  }

  if (role && user.role !== role) {
    return <Navigate to="/" />;
  }

  return children;
};

export default ProtectedRoute;

🤓 Explicando o código 📝

O ProtectedRoute atua como um guardião: verifica se existe usuário e se o user.role corresponde ao papel exigido. Se qualquer verificação falhar, usa o <Navigate> para redirecionar o usuário.

5ª Parte — Proteger as rotas no App.jsx

No App.jsx, proteja as rotas /criar-produto e /produto/:id para que apenas usuários com papel admin possam acessá-las.

Gabarito: 

import { BrowserRouter, Routes, Route } from 'react-router-dom';
import Login from './components/aulas-integradas/Login';
import Registrar from './components/aulas-integradas/Registrar';
import Home from './components/aulas-integradas/Home';
import CriarProduto from './components/aulas-integradas/CriarProduto';
import EditarProduto from './components/aulas-integradas/EditarProduto';
import ProtectedRoute from './components/ProtectedRoute';

const App = () => {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/login" element={<Login />} />
        <Route path="/registrar" element={<Registrar />} />
        <Route
          path="/criar-produto"
          element={
            <ProtectedRoute role="admin">
              <CriarProduto />
            </ProtectedRoute>
          }
        />
        <Route
          path="/produto/:id"
          element={
            <ProtectedRoute role="admin">
              <EditarProduto />
            </ProtectedRoute>
          }
        />
      </Routes>
    </BrowserRouter>
  );
};

export default App;

🤓 Explicando o código 📝

Envolvemos o componente com ProtectedRoute passando role="admin". Assim, apenas usuários com esse papel conseguem acessar a criação e a edição de produtos.

6ª Parte — Fazer o Login salvar o usuário no contexto

No Login.jsx, adicione um campo de seleção de role (para testar admin e employee) e, ao enviar o formulário, chame a função login do contexto salvando o usuário e redirecione para a Home.

Gabarito: 

import { useState } from 'react';
import { useNavigate } from 'react-router-dom';
import { useAuth } from '../../context/AuthContext';

const Login = () => {
  const [formData, setFormData] = useState({
    email: '',
    senha: '',
    role: 'employee',
  });
  const { login } = useAuth();
  const navigate = useNavigate();

  const handleChange = (e) => {
    const { name, value } = e.target;
    setFormData({ ...formData, [name]: value });
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    login({ email: formData.email, role: formData.role });
    navigate('/');
  };

  const inputStyle = {
    width: '100%',
    padding: '8px',
    marginTop: '4px',
    border: '1px solid #ccc',
    borderRadius: '4px',
  };

  return (
    <div style={{
      maxWidth: '400px',
      margin: '40px auto',
      padding: '24px',
      border: '1px solid #ddd',
      borderRadius: '8px',
      boxShadow: '0 2px 8px rgba(0,0,0,0.1)',
    }}>
      <h1 style={{ textAlign: 'center' }}>Login</h1>
      <form
        onSubmit={handleSubmit}
        style={{ display: 'flex', flexDirection: 'column', gap: '12px' }}
      >
        <div>
          <label>Email:</label>
          <input
            type="email"
            name="email"
            value={formData.email}
            onChange={handleChange}
            placeholder="Digite seu email"
            style={inputStyle}
          />
        </div>
        <div>
          <label>Senha:</label>
          <input
            type="password"
            name="senha"
            value={formData.senha}
            onChange={handleChange}
            placeholder="Digite sua senha"
            style={inputStyle}
          />
        </div>
        <div>
          <label>Role:</label>
          <select
            name="role"
            value={formData.role}
            onChange={handleChange}
            style={inputStyle}
          >
            <option value="employee">employee</option>
            <option value="admin">admin</option>
          </select>
        </div>
        <button
          type="submit"
          style={{
            padding: '10px',
            backgroundColor: '#0073e6',
            color: '#fff',
            border: 'none',
            borderRadius: '4px',
            cursor: 'pointer',
          }}
        >
          Entrar
        </button>
      </form>
    </div>
  );
};

export default Login;

🤓 Explicando o código 📝

Ao enviar o formulário, chamamos login({ email, role }) que atualiza o contexto (e o localStorage) com o usuário logado, e depois usamos navigate('/') para voltar à Home. Como não temos um endpoint real de login na API, simulamos a autenticação escolhendo o papel no formulário.

7ª Parte — Renderização condicional na Home

No Home.jsx, use o useAuth para exibir o usuário logado e mostrar os botões Criar Produto, editar e deletar apenas para admin. O employee deve ver apenas a lista de produtos, sem botões de ação.

Gabarito: 

import { useState, useEffect } from 'react';
import axios from 'axios';
import { Link, useNavigate } from 'react-router-dom';
import { useAuth } from '../../context/AuthContext';

const Home = () => {
  const [produtos, setProdutos] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);
  const { user } = useAuth();
  const navigate = useNavigate();

  const carregarProdutos = () => {
    axios
      .get('https://projeto-node-step-t5i1.vercel.app/produtos')
      .then((response) => {
        setProdutos(response.data);
        setLoading(false);
      })
      .catch((err) => {
        setError(err.message);
        setLoading(false);
      });
  };

  useEffect(() => {
    carregarProdutos();
  }, []);

  const deletarProduto = async (id) => {
    try {
      await axios.delete(
        `https://projeto-node-step-t5i1.vercel.app/produtos/${id}`
      );
      carregarProdutos();
    } catch (err) {
      console.error('Erro ao deletar:', err);
      alert('Erro ao deletar produto');
    }
  };

  if (loading) return <p>Carregando produtos...</p>;
  if (error) return <p>Erro: {error}</p>;

  return (
    <div style={{ maxWidth: '600px', margin: '40px auto', padding: '0 20px' }}>
      <h1>Home</h1>
      <p>
        Usuário: {user ? user.email : 'não logado'} ({user ? user.role : '-'})
      </p>

      {user?.role === 'admin' && (
        <Link to="/criar-produto">Criar Produto</Link>
      )}

      <h2>Produtos</h2>
      <ul>
        {produtos.map((produto) => (
          <li key={produto._id} style={{ marginBottom: '8px' }}>
            {produto.nome}{' '}
            {user?.role === 'admin' && (
              <>
                <button onClick={() => navigate(`/produto/${produto._id}`)}>
                  editar
                </button>{' '}
                <button onClick={() => deletarProduto(produto._id)}>
                  deletar
                </button>
              </>
            )}
          </li>
        ))}
      </ul>
    </div>
  );
};

export default Home;

🤓 Explicando o código 📝

Usamos user?.role === 'admin' com o operador && para renderizar condicionalmente (Aula 5) o link "Criar Produto" e os botões "editar"/"deletar". O operador ? (optional chaining) evita erro quando user é null. Assim, um employee (ou um usuário não logado) só vê a lista.
